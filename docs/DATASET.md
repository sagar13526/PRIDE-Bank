# Predictor datasets

The Markov predictor learns from **telemetry samples**: every 10 ms the sampler records how many transfers
are active, how many are waiting, the longest wait chain, the number of locked accounts, and the load
state (0 NORMAL, 1 CONTENTION, 2 HIGH_RISK, 3 DEADLOCK). The data is generated by our own simulator, so it
is **synthetic**: no real bank data is used.

## Where it lives

| Place | What |
|---|---|
| `data/*_samples.csv`, `data/*_runs.csv` | CSV files written by `benchmark_suite --collect`; read by `analysis/validate_predictor.py` |
| MySQL tables `telemetry_run`, `telemetry_sample` | the same data, one row per run / per sample, grouped by a `dataset` name |
| MySQL table `markov_counts` | the learned transition counts, saved and reloaded by `PredictorService::saveCounts / loadCounts` |
| Views in `sql/analysis_views.sql` | `v_run_summary`, `v_state_summary`, `v_transition_counts` |

## Datasets

| `dataset` | Files | Runs | Samples | Collected with |
|---|---|---|---|---|
| `train` | `data/telemetry_*` | 81 | 40,754 | `--collect 81 data/telemetry 1000 mixed` |
| `heldout` | `data/heldout_*` | 54 | 7,979 | separate seeds, kept aside for testing |
| `indep` | `data/indep_*` | 27 | 12,027 | `--collect 27 data/indep 9000 mixed` |

`indep` uses new seeds (9000 to 9026) and was collected in a separate session. It covers every combination
of 4/8/16 threads, 5/10/20 accounts and hot-spot probability 0/0.5/0.9 once, with 20 transfers per thread,
detection mode and "youngest" victims. It is independent of `train` and `heldout` because no run or seed is
shared. It is **not** a different system: it comes from the same simulator.

State mix of `indep` (from `v_state_summary`): NORMAL 3.8%, CONTENTION 19.8%, HIGH_RISK 48.7%, DEADLOCK 27.7%.

## Commands

```bash
# load CSV files into MySQL (tables must exist: sql/schema.sql, sql/analysis_views.sql)
python3 tools/import_telemetry.py indep data/indep

# look at the data
mysql pride_bank -e "SELECT * FROM v_state_summary WHERE dataset='indep';"
mysql pride_bank -e "SELECT * FROM v_transition_counts WHERE dataset='indep';"

# write a dataset back out as CSV for the Python validation
python3 tools/export_telemetry.py indep data/indep_export
python3 analysis/validate_predictor.py data/telemetry 5 data/indep_export

# collect a new dataset
./build/benchmark_suite --collect 27 data/mynew 12000 mixed
```

The Python tools need `pip install pymysql` and use the `PRIDEBANK_DB_*` environment variables.

## Saving and loading the model

```cpp
auto& svc = predict::PredictorService::getInstance();
svc.saveCounts("default");        // stores the transition counts in markov_counts
svc.loadCounts("default", 0.5);   // reloads them, every count scaled by 0.5
```

The scale factor (`keep`) makes old data count for less, because a model trained on one load level was
badly calibrated on another (see `analysis/validation_report.md`). `loadCounts` replaces the current chain and
returns false, changing nothing, if the model name is unknown.
